# packages/sdk

The source of truth for HarnessFlow's typed contracts. Edit `proto/` and
`schema/`; everything in `gen/` is generated by `make proto` and committed so a
fresh clone never needs codegen tools.

| Path | What | Source of truth for |
| --- | --- | --- |
| `proto/` | Protobuf service + message definitions | All RPC types (Go, Python, TS) |
| `schema/workflow.schema.json` | JSON Schema for the workflow YAML DSL | Workflow DSL — Pydantic + Go structs |
| `gen/go/` | Generated Go: protobuf, Connect-Go services, schema structs. Own Go module, joined via the repo-root `go.work`. | — |
| `gen/python/` | Generated Python: protobuf `_pb2` modules + the Pydantic `workflow_schema.py` | — |
| `gen/ts/` | Generated TypeScript: protobuf-es v2 messages (consumed by Connect-ES) | — |

## Regenerating

```bash
make proto
```

Runs `buf lint` + `buf generate`, tidies the generated Go module, and runs
`datamodel-codegen` (Pydantic) and `go-jsonschema` (Go structs) over the JSON
Schema. It is idempotent — CI enforces `make proto && git diff --exit-code`.

Tool versions are pinned in the `Makefile` (`DATAMODEL_CODEGEN_VERSION`,
`GO_JSONSCHEMA_VERSION`) and `buf.gen.yaml` (remote plugins) so output is
reproducible.

## Changing contracts

- Proto changes: edit `proto/`, run `make proto`. `buf` breaking-change rules
  (`buf.yaml`) guard against incompatible edits.
- Workflow DSL changes: edit `schema/workflow.schema.json` **and**
  `packages/workflow-dsl/SPEC.md` in the same commit, and write an ADR — see
  `Project-Documentation/decisions/`.
