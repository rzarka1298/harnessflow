# Research Extensions (v1.1) — Overview

**Branch:** `research/v1.1` (do not merge to `main` until eval gate passes).
**Locations:** `apps/policy-learner/`, `apps/workflow-optimizer/`.
**Tag at completion:** `v1.1.0-research`.

Both features build *on top of* the v1.0 platform shipped in week 12. This is the design narrative: HarnessFlow is good enough infra to be its own substrate for AI-driven self-improvement.

These are **research prototypes**, not production features. The writeups (`retry-policy-learner.md`, `autonomous-mutation.md`, `ab-results.md`) are as much of the deliverable as the code.

## Week 13 — Contextual-bandit retry policy learner

**What:** A Python service that observes historical retry outcomes from Postgres, trains per-(workflow, step) Thompson-sampling models, and serves retry recommendations via a Connect RPC the worker calls on activity failure.

**Why not deep RL:** A portfolio project will not generate enough data to train deep RL meaningfully. Contextual bandits with Thompson sampling are the *right* algorithm for this data regime and what serious AI infra teams actually deploy. Honesty here is itself the signal.

See [`retry-policy-learner.md`](./retry-policy-learner.md) and [ADR-0007](../decisions/0007-contextual-bandit-not-deep-rl.md).

## Week 14 — Autonomous workflow mutation

**What:** A scheduled Python service that observes eval scores, identifies the worst-performing workflow, asks Claude (with constrained structured output) to propose a mutation, applies it to a YAML copy, runs a quick local eval, opens a PR via `gh`, and lets the week-8 eval gate decide whether to merge.

**Safety rails:**
- Only mutates files in `packages/examples/workflows/`.
- Always opens a PR (never direct push).
- Daily caps: 3 PRs, $5 LLM spend.
- Structured output enforced via Anthropic tool use — no free-form code.

See [`autonomous-mutation.md`](./autonomous-mutation.md) and [ADR-0008](../decisions/0008-autonomous-mutation-safety-model.md).

## Why this matters to recruiters

- **OpenAI / Anthropic:** self-improving agents grounded in a platform with audit + eval gates. The exact "agents need infrastructure" thesis.
- **Temporal:** the mutation agent runs as a Temporal cron workflow — eat-your-own-dogfood at the platform layer.
- **Datadog:** the bandit learns from observability data; the optimizer is monitored by the same system.
- **AI infra startups (Braintrust, Patronus, Helicone):** demonstrates internalization of "evals as the source of truth, used as a control signal."
