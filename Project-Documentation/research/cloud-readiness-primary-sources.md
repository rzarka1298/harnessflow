# Cloud-readiness primary-source findings

Checked 2026-10-13 against the repository's `infrastructure/terraform/envs/demo/` and `infrastructure/helm/harnessflow/`. This is a repository-side deployment audit, not evidence that AWS resources were created or that an end-to-end cloud run passed.

## Deployment blockers

1. **RDS connectivity (remediated in this repository change):** `rds.tf` selects PostgreSQL 16.4, but the chart initially hardcoded `sslmode=disable` in the API, worker, and migration Job. RDS PostgreSQL 15+ defaults `rds.force_ssl=1`, which requires SSL/TLS connections. The chart now defaults to `require` for external Postgres and rejects `disable`; bundled local Postgres remains unencrypted. Certificate verification (`verify-full` with a trusted CA mounted into every client) is still needed before a public deployment. [AWS RDS PostgreSQL SSL documentation](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/PostgreSQL.Concepts.General.SSL.html)

2. **EKS version and cost (partly remediated):** `variables.tf` initially defaulted to Kubernetes 1.31. AWS lists its standard-support end as 2025-11-26 and extended-support end as 2026-11-26. As of this audit date, a new 1.31 demo would incur extended-support pricing, **$0.60 per cluster-hour** rather than **$0.10** ($14.40/day versus $2.40/day for the control plane alone). The template default is now 1.35, which AWS currently lists in standard support. Verify add-on/module/chart compatibility in a real cluster and re-estimate the full stack before applying. [EKS version calendar](https://docs.aws.amazon.com/eks/latest/userguide/kubernetes-versions.html), [EKS pricing](https://aws.amazon.com/eks/pricing/)

3. **Terraform state and DB password:** The current configuration creates a `random_password` and passes it into both RDS and a Secrets Manager secret, so the password is still in Terraform state. The current local backend leaves that state on the operator's machine. For a cloud deployment, bootstrap restricted, encrypted, versioned S3 state and enable S3 lockfiles before the first apply. The Terraform README's recommendation for a new DynamoDB lock table is outdated: HashiCorp now documents DynamoDB-based locking as deprecated. RDS-managed master credentials can avoid Terraform generating and tracking the plaintext master password. [Terraform S3 backend](https://developer.hashicorp.com/terraform/language/backend/s3), [Terraform sensitive-data guidance](https://developer.hashicorp.com/terraform/language/manage-sensitive-data), [RDS-managed password](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/rds-secrets-manager.html)

## Security and operational choices before a public service

4. **Cache transport:** The Terraform Redis resource is a single `aws_elasticache_cluster` without in-transit encryption or authentication, and the chart's external Redis config has only host/port. AWS documents TLS on node-based Redis through a replication group and notes that client TLS support must be enabled. Do not switch on ElastiCache TLS in isolation; first add and verify TLS/auth-capable client configuration, then select the appropriate ElastiCache resource and access control. [ElastiCache in-transit encryption](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/in-transit-encryption.html), [ElastiCache authentication](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/auth-iam.html)

5. **Cluster endpoint:** `eks.tf` enables a public API endpoint without an allowed-CIDR restriction. AWS says this is internet-reachable, though IAM and Kubernetes RBAC still protect access. For a private service, use a private endpoint; for a laptop-operated demo, restrict public CIDRs and enable private access so nodes can still reach the control plane. [EKS endpoint access](https://docs.aws.amazon.com/eks/latest/userguide/cluster-endpoint.html), [EKS endpoint configuration](https://docs.aws.amazon.com/eks/latest/userguide/config-cluster-endpoint.html)

6. **Secret delivery:** `env.keys.create=true` puts LLM keys into Helm values and the resulting release record. Helm states release information contains chart and values content, potentially including sensitive data. Prefer the chart's `env.keys.existing` path with an out-of-band Kubernetes Secret/external secret; enable Kubernetes Secret encryption at rest and restrict RBAC. Avoid sending keys via `helm --set` or committing values. [Helm release storage warning](https://helm.sh/docs/topics/advanced/), [Kubernetes Secret practices](https://kubernetes.io/docs/concepts/security/secrets-good-practices/)

7. **Future CI deployment credentials:** If a deployment workflow is added, GitHub Actions OIDC can assume an AWS role without storing a long-lived AWS access key in GitHub. Scope the AWS trust policy to this repository and intended branch/environment, and protect that environment. This is preparation guidance; no AWS trust role exists here yet. [GitHub's AWS OIDC guidance](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-aws)

## Suggested order

Fix the chart's managed-Postgres connection path and test its render; update supported EKS version/cost assumptions; choose the intended cloud product shape and credentials/workspace model; then harden state, cache, endpoint, and secret delivery before any apply. The existing IRSA approach remains supported by AWS, so switching to Pod Identity is optional rather than a prerequisite. [AWS EKS service-account IAM options](https://docs.aws.amazon.com/eks/latest/userguide/service-accounts.html)
